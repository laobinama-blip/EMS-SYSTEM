# Reewell 服务器 BOM 配置器设计

## 目标

为 Reewell EMS 前端新增一个产品 BOM 配置页面，用于售前按管理车辆数量和 HA 高可用需求生成硬件服务器配置，并实时计算成本。页面体验参考高端汽车选配器：选择规模、可靠性和部件选项后，右侧持续展示总成本、BOM 明细和推荐方案。

## 关键假设

- 目标仓库为 `EMS-SYSTEM-main`，页面加入 `ems-frontend` 现有 React + Vite 应用。
- 车辆规模分为 10、50、100、300、500、1000 辆以下六档。
- 车辆规模决定基础服务器规格、存储容量、网络设备和实施服务档位。
- HA 开启后，应用服务器、数据库服务器、核心交换和维保服务按冗余要求增加。
- 当前成本为演示用 BOM 单价，结构要便于替换成真实采购价。

## 页面结构

- 顶部导航新增 `BOM配置` 标签，保持现有 Reewell 应用壳。
- 主区域左侧为配置工作台：
  - 车辆规模档位选择。
  - HA 高可用开关。
  - 推荐服务器规格摘要。
  - 可选项：备份存储、GPU 加速、实施服务年限。
- 主区域右侧为固定成本摘要：
  - 总成本、硬件成本、服务成本、HA 增量。
  - 推荐拓扑和交付备注。
  - 导出 BOM、提交方案按钮。
- 下方展示 BOM 明细表，逐项列出分类、型号、数量、单价和小计。

## 数据与计算

计算逻辑拆到独立模块：

- `src/bom/bomData.ts` 保存车辆档位、部件单价、服务选项。
- `src/bom/bomMath.ts` 提供 `buildBomQuote(options)`，输入配置，输出推荐档位、明细和成本汇总。
- `src/bom/ServerBomPage.tsx` 负责交互状态和渲染。

计算规则：

- 基础应用服务器数量随车辆档位递增，HA 开启后核心服务器数量翻倍。
- 数据库服务器在 100 辆及以上独立配置，HA 开启后数据库节点翻倍。
- 300 辆及以上加入管理/观测节点。
- 500 辆及以上默认推荐双万兆核心网络。
- GPU、备份存储、服务年限作为用户选项追加成本。

## 验证

- 为 `buildBomQuote` 写单元测试，覆盖规模档位、HA 数量、可选项和成本合计。
- 运行 `npm run typecheck`、`npm run build`。
- 启动本地 Vite 服务，用浏览器验证桌面和移动布局，以及切换车辆规模、HA、可选项时成本实时变化。
